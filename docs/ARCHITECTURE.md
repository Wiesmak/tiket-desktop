# Architecture — Phase 1

Adapted from the owner's 2026-11-12 architecture starter ZIP after reading all six design documents and both conceptual wireframes. Those are design references, not evidence of a working product. Historical .NET 10, Visual Studio template creation, absent repository and empty main-branch assumptions are superseded by this existing .NET 11 / Rider / master checkout.

The preserved WinUI UI project owns App, MainWindow, native TitleBar, MicaBackdrop, RootFrame and MainPage. MainPage hosts NavigationView and temporary mock controls. No UI event dispatches RPCs. Tiket.Desktop.Application contains only navigation/presentation state and endpoint validation, without WinUI or protobuf dependencies. Tiket.Desktop.Contracts isolates generated C# messages and client stubs for all eight services / 37 unary RPCs. Tiket.Desktop.Tests tests these boundaries without a WinUI window. There are no empty infrastructure/domain assemblies, service container or financial engine.

The backend alone owns money, race lifecycle, authoritative pricing/versions, settlement and print dispatch. Desktop must never connect directly to PostgreSQL, serial ports or a competing print queue. Future gRPC adapters will map generated types into application state and reuse bounded HTTP/2 channels, deadlines and cancellation. Backend traffic uses validated TLS; explicit development plaintext is limited to 127.0.0.1. Schema availability is not authorization.

Phase 1 adds pure PreviewPresentation policy (effective-width layout, fictional print labels and builder descriptions) and a typed session-only AppearanceState to Application. No new dependencies or persistence are needed. MainPage retains native controls in place; navigation, step changes and theme changes never recreate the workspace. Code-behind handles WinUI visibility, navigation/focus, theme integration and selection of XAML layout states using measured workspace width. The 900-pixel content threshold and primary-column caps are documented in UX_SPEC.md; the corrective pass removes the global cap and shares the title/content container.

Future mutations require a durable encrypted exact-request journal before sending. Store serialized method/request, original IDs and idempotency key, profile/event/POS/subject binding, and PREPARED/SENDING/UNKNOWN/ACKED/rejected state. Timeout or cancellation after sending means unknown outcome, never proof of failure. Reconcile by identical request/key under the same subject; do not allocate another coupon. This journal is deferred, not implemented.

Future recent tickets cover locally known acknowledged IDs and known-player lookups. They cannot promise POS-wide history. CreateRaceDay takes a complete immutable DRAFT; preparation remains a local draft until one-shot creation. Configuration, identity, persistence and real adapters will be introduced only with their own tests in later phases.

## Phase 2 implementation

The existing Application project now owns validated immutable ConnectionProfile, managed JSON loading, NativeOidcLogin, LoopbackCallback, signed identity validation, ConnectionSession and a narrow IReadOnlyBackend boundary. An additional empty infrastructure project was unnecessary. Application references Contracts and the pinned OIDC/JWT libraries. UI code-behind owns native controls, dispatcher-affine session orchestration, expiry timer and cancellation on window close; it contains no token fields. Tests reference the shared ASP.NET Core framework only for ephemeral HTTP/2 wire integration.

Channels belong to an active profile/operator lifetime. Per-call metadata uses the current access token; Ping has no bearer header. Cancellation plus monotonically changing generation suppress old login/read completions. No persistence/cache layer, mutation adapter, background polling, automatic retries or refresh handler is introduced. Actual protobuf responses are shown in Settings and compact SERVER context, separate from fixtures. [Setup and boundaries](CONNECTION_AND_OIDC.md).

## Phase 3 quotation

CashierComposer in Application owns an immutable typed QuoteDraft (pool, mode, ordered SlotChoice entries, stable box UUID order and exact units text), cloned day/race context, elementary validation and independent QuoteState. It has no WinUI dependency, pricing/expansion engine or persistence. Normal and Wall map to positional protobuf; Box maps to the separate box oneof. Every edit or context update increments an editor revision, cancels pending work and clears the retained response before notifying the view. Each asynchronous operation owns its request and revision; completion checks revision and cancellation before publishing a cloned authoritative response. Day/race context is cloned against external alias mutation. Canonical response rendering follows the returned variant and order.

ConnectionSession owns the composer and remains the credential boundary. Its quote delegate verifies the active authenticated profile, authorized loaded event/race and expiry, links editor and session cancellation, reuses IReadOnlyBackend and checks session generation after transport. Clear/read refresh invalidates the editor before changing context. UNAUTHENTICATED expires the session; other quote errors change quote state without rewriting connection state as READY. ReadOnlyBackend adds only generated BettingService.QuoteCouponAsync with the existing origin, one Bearer access-token header and bounded deadline. No raw credentials reach MainPage. MainPage.Quote.cs adapts server races/runners into native controls and does not calculate financial values.

No project, direct package, protocol refresh, mutation adapter, journal or printer integration is introduced. Capture-only synthetic injection is excluded from final application source.
